# 论文装配 SOP（IMRaD → docx）

> **用途 / Purpose**：把「素材 → IMRaD 结构 → docx 交付件」的装配动作定死为可照单执行的作业流程——逐节自查、Claim-Evidence 映射、**docx 卫生断言**、引用格式口径。
> **版本 / Version**：v1.0（2026-09-21 · 生成侧强化批 3 · V-M7）
> **模块指针**：V-M7 论文装配 PAPER（`VESI-ENGINE.md` §1 · §3「docx = `assert_delivery_hygiene`，FAIL=0」行 · §4 RB-V4）｜装载 `workflows/09-论文写作.md`
> **纪律**：① 本 SOP **不复制** workflows 正文；② 装配前先过上游门禁（数据分析「三证齐」、图件三闸）；③ **交付件禁止经 Word 另存**（见 §4，实测坑）；④ 引用格式未定前按 §5 **默认数字顺序制**并全程标 `[待定]`。

## 1 · 节次结构清单（IMRaD）

| # | 节 | 装配产物 | 素材来源（上游） | 必含要素 |
|---|---|---|---|---|
| 1 | **Title** | 标题行（+ 副标题/编号规则） | 课题名 + 目标轨命名要求 | 研究对象 + 制剂 + 核心问题；不加未验证结论词 |
| 2 | **Abstract** | 结构式摘要（目的/方法/结果/结论） | 全文关键数字（引 §3 Claim-Evidence 表） | 结构与正文一致；数字与结果节**逐位一致**；不出现正文没有的结论 |
| 3 | **Introduction** | 背景 → 缺口 → 目的 | 综述 + 证据表（V-M1） | 缺口句明确；引用编号连续 |
| 4 | **Methods** | 材料/方法/分组/统计/伦理 | 设计卡 + 实验记录（V-M2/M3） | 可复现（参数齐）；统计方法**实验前定稿**；n 与重复类型声明 |
| 5 | **Results** | 结果段 + 图/表 + 图注 | 分析报告 + 图件（V-M4/M5/M6） | 只述事实与统计；误差棒含义（SD/SEM）声明；精确 p 值 |
| 6 | **Discussion** | 解释 → 与文献对照 → 局限 → 展望 | 证据表 + 文献对照 | 推断/假说显式标注；结论不超数据范围 |
| 7 | **Conclusion** | 结论 3–5 条 | Results/Discussion | 与目标轨字数/条数要求对齐 |
| 8 | **References** | 引用表（数字顺序制） | `references/引用格式卡.md` | 与文内 `[n]` 一一对应；元数据过 esummary |

> 各节的写作要求与话术以 `workflows/09-论文写作.md` 为准；本表只管**装配顺序与必含要素**。

## 2 · 逐节自查 checklist（装配后逐项打勾）

### 通用（每节都查）

- [ ] 术语/单位与 `references/数据条目字典.md` 口径一致（无同义双拼、无隐含单位）
- [ ] 每个数字可回溯（三态齐全；`hypothesis` 未混入结果数字）
- [ ] 图/表编号连续且**在正文中先引用后出现**
- [ ] 无字面 Markdown 残留（`**` 等；断言脚本会查）
- [ ] 无占位符残留（`<…>`、`待补`、`TBD` 全文清零，除有意留白并已登记）

### Title / Abstract

- [ ] 标题不含「首次/突破」类未证实断言
- [ ] 摘要数字与结果节逐位一致（**机械比对**，非人工目视）

### Introduction

- [ ] 缺口句明确（已有研究缺什么 → 本课题补什么）
- [ ] 引用编号按首次出现顺序，无跳号/重号

### Methods

- [ ] 可复现：动物品系/性别/体重范围、给药途径与剂量口径、采样时点与体积、检测方法参数齐
- [ ] 统计方法与 n 在**实验前**定稿（引用设计卡）
- [ ] 伦理/合规声明就位（按目标轨要求）

### Results

- [ ] 每图/表有自含图注（不看正文可理解）
- [ ] 误差棒含义声明（统一 SD + 个体散点 / SEM 须注明理由）
- [ ] p 值报精确值；多重比较已校正；小样本未硬标显著
- [ ] 结论句不超出数据范围

### Discussion / Conclusion

- [ ] 与文献对照处引用可核（作者/年份/期刊过实证）
- [ ] 局限节实写（不空话）；推断与假说显式标注
- [ ] 结论条数与目标轨要求一致

### References

- [ ] 文内 `[n]` 与列表一一对应（无孤号/无未引条目）
- [ ] 期刊名缩写合规；DOI/PMID 可解析
- [ ] 引用格式符合目标要求（见 §5，未定则标 `[待定]`）

## 3 · Claim-Evidence 映射（装配的第 0 步）

> **指针**：映射表模板 = `templates/Claim-Evidence映射表.md`（批 3 件）。
> 该件未落盘时，按 §3.2 表结构**手写同结构表**，不得跳过本步。

### 3.1 步骤（五步 · 逐条走）

1. **抽 claim**：从 Results/Discussion 逐句抽出**可判定真假的陈述**（一 claim 一行，编号 `C-<节>-<序号>`）。
2. **配证据**：每条 claim 指定证据（`fig` / `table` / `data` / `ref`），写明**具体位置**（图号/表号/条目名/文献编号）。
3. **标三态**：`fact` / `inference` / `hypothesis`（口径同 `references/数据条目字典.md` §3）。
4. **核一致性**：claim 中的数字与证据中的数字**逐位一致**；不一致先修证据链，不改措辞掩盖。
5. **记缺口**：无证据支撑的 claim → 进缺口清单（动作 = 补数据 / 降级表述 / 删除），**空缺不得静默带过**。

### 3.2 表结构（手写时同此列）

| claim_id | claim 文本（节 + 句号） | 证据类型 | 证据位置 | 三态 | 一致性 | 缺口动作 |
|---|---|---|---|---|---|---|
| `C-R-01` | `<该句原文>` | `fig` / `table` / `data` / `ref` | `<图1 / 表2 / 条目名 / [n]>` | `fact` / `inference` / `hypothesis` | `一致` / `不一致(已修)` | `<补数据 / 降级 / 删除 / —>` |

## 4 · docx 卫生（交付件硬约束）

### 4.1 禁令：交付件禁止经 Word 另存

**实测坑（内部复现记录；该待办件不随包分发）**——Word 再保存会：

| # | 后果 | 影响 |
|---|---|---|
| a | Heading `styleId` 被规范化（自定义 → `Heading1/2/3` 或数字 ID） | 目录/样式被静默改写，交叉引用与格式链漂移 |
| b | 丢失 `settings.xml` 的 `updateFields` | 打开时**不再自动刷新域**（页码/目录停在旧值） |
| c | 页脚 `PAGE` 域重复 | 渲染成「第 11 页」这类错页码 |

**纪律**：交付件只走「脚本生成 → 断言 → 冻结 md5」。需要翻看时**开副本**，不碰交付件本体。

### 4.2 域更新要点

1. 生成阶段即写入 `w:updateFields`（打开时刷新）**并**同时把域值**落定**（不依赖打开方刷新）。
2. 页脚/页眉域**逐件核查**：`PAGE` 域每文件只应有 1 个；重复即 FAIL。
3. 目录（`TOC \o`）域必须存在且层级与标题样式匹配。
4. 任何一次「另存/转换/合并」之后，**重跑 §4.3 断言**再谈交付。

### 4.3 断言命令（`assert_delivery_hygiene.py`）

脚本正本：`scripts/assert_delivery_hygiene.py`（路径系统根相对；脚本以 `sys.argv` 收参）。

```bash
# 基本用法：逐件卫生审计（Heading 定义/引用、updateFields、TOC 域、表数、字面 **、汉字数、页眉页脚域）
python scripts/assert_delivery_hygiene.py <交付件1>.docx <交付件2>.docx

# 带 md5 冻结核验：--expect <md5>=<路径>（可重复多个）
python scripts/assert_delivery_hygiene.py \
  kb/<交付件>.docx \
  --expect <期望md5>=kb/<交付件>.docx
```

- **退出码**：`0` = 结构卫生项通过（若给了 `--expect` 则 md5 亦相符）；`1` = 有 FAIL；`2` = 未给参数（打印用法）。
- **输出要点**：逐件打印 `md5` / Heading 定义与引用 / `updateFields` / TOC 域数 / tables / 字面 `**` / 汉字数 / **页眉页脚域**；末行 `HYGIENE PASS` 或 `HYGIENE HAS FAILURES`。
- **通过线**：**FAIL = 0**（`[WARN]` 须逐条裁定并留痕，不得静默忽略）。
- **留证**：断言输出 + 交付件 md5 一并记入交接卡（`VESI-ENGINE.md` §7）。

### 4.4 docx 卫生 checklist

- [ ] 全文 `**` 字面残留 = 0
- [ ] Heading 1/2/3 定义存在且引用与目录层级一致
- [ ] `updateFields` 在位（或已声明「定稿后可接受」并留痕）
- [ ] TOC 域存在；目录条目与标题一致
- [ ] 页脚/页眉 `PAGE` 域各文件 = 1 个（无重复）
- [ ] 套用模板时**样式名/样式 ID 与模板一致**（不依赖 Word 归一化）
- [ ] 交付件 md5 已冻结并记入交接卡
- [ ] **交付件自断言后未经 Word 另存**（时段核查：产件→断言→冻结之间无第三方工具写入）

## 5 · 引用格式小节

> **口径状态：`[待定：按目标期刊 / 赛事要求]`** —— 未定前**默认采用数字顺序制（Vancouver 风格）**。
> 格式细则、条目模板与示例骨架见 `references/引用格式卡.md`；本节只做**装配期取用**。

| 要素 | 格式 A（目标期刊/赛事 · 待填） | 格式 B（当前默认 · 数字顺序制） |
|---|---|---|
| 文内标注 | `[待填]` | `[n]`（多篇 `[1,2]`；连续 `[1-3]`） |
| 作者数阈值 / et al. 触发 | `[待填]` | `[待填]`（默认：>6 作者取前 6 + et al.，按目标要求复核） |
| 期刊名 | `[待填]` | NLM 标准缩写 |
| 卷期页码 | `[待填]` | `年;卷(期):起-止页` |
| DOI / PMID | `[待填]` | DOI 优先（有则必填） |
| 排列顺序 | `[待填]` | 按**文内首次出现顺序**编号 |

**装配期纪律**：① 格式未定前**不得**混用两种体例；② 引用元数据一律过 NCBI esummary（对齐 `workflows/08-数据处理与可视化.md` §LS-8-5），**禁止凭记忆填作者/年份/PMID**；③ 格式一经确定，本节表格「格式 A」列填实并同步 `引用格式卡.md`。

## 6 · 装配流程（照单执行）

```text
① 上游门禁：分析报告「三证齐」+ 图件过闸（V-M4/M6）
② Claim-Evidence 映射表填毕（§3；缺口清单已处置或登记）
③ 逐节装配（§1 顺序）→ 逐节自查（§2）
④ 引用表与文内 [n] 对质（机械计数，不复点不算过）
⑤ docx 卫生断言（§4.3）→ FAIL=0
⑥ 冻结 md5 + 记交接卡（`VESI-ENGINE.md` §7）
⑦ 交付件**不再经 Word 另存**；后续修改走新版本号 + 重跑全部断言
```
